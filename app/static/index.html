01 / text

Send original prose, labeled sections, or structured JSON objects up to 2,000 characters.

Pass 2–16 competing labels as a list of names or a dictionary with concise descriptions.

Receive the winning label and native softmax scores across all candidates.

Your first request

Set BASE_URL to your service URL and API_KEY to your access key. The server accepts any key in its API_KEYS list. Send one key per request. You can also send requests using the Authorize button in the docs.

curl "$BASE_URL/api/classify" \
  -H "Authorization: Bearer $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "I was charged twice for the same order.",
    "task": "department",
    "prompt": "Which team should handle this request?",
    "labels": {
      "billing": "Charges, refunds, and invoices",
      "technical": "Website, login, or technical outages"
    }
  }'

Returns choice (the top-scoring candidate) and probabilities (native softmax scores across all candidate labels in request order).

Competing candidates, clear context

Use a string by default for text, and define competing candidate labels in labels. For yes/no or safety gates, provide two meaningful competing options rather than a single statement.

{
  "text": "git status -s && pytest -q",
  "task": "command_safety",
  "prompt": "Classify the risk category of running this command in a developer workspace.",
  "labels": {
    "read_or_test": "Inspects status or runs local tests without destructive side effects",
    "state_mutation": "Edits source files, installs packages, or commits changes",
    "destructive": "Deletes data, resets git history, or modifies system configuration"
  }
}
  • Pass bare label lists (e.g. ["negative", "neutral", "positive"]) when label names are self-explanatory.
  • Add concise label descriptions and an optional prompt when domain boundaries need disambiguation.
  • Keep complete prepared inputs within 1,024 subword tokens; oversized inputs return 422 instead of truncating silently.
