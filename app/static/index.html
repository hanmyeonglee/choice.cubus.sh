Your first request

Set BASE_URL to your service URL and API_KEY to your access key. The server accepts any key in its API_KEYS list. Send one key per request. You can also send requests using the Authorize button in the docs.

curl "$BASE_URL/api/evaluate" \
  -H "Authorization: Bearer $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "state": "I was charged twice for the same order.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "billing": "Charges and invoices",
          "technical": "Technical issues"
        }
      },
      "duplicate_charge": {
        "type": "noul",
        "instructions": "The customer was charged twice for the same order."
      }
    }
  }'

Results are returned under answers, keyed by question ID. Choice probabilities are normalized classification scores; noul is the raw classification score for a single statement.

Free-form state, clear context

Use a string by default. Send documents and reviews as original text, and add short labels when combining different kinds of information. No specific keys or schema are required.

Customer message:
I was charged twice for the same order.

Payment records:
Two completed payments belong to order A123.

Current status:
No refund has been issued.
  • Identify speakers and message order in conversations, and times and current status in histories.
  • Separate claims from verified facts, and preserve relationships, units, and negation.
  • Put source material in state, and questions and evaluation criteria in questions.

Objects and arrays are serialized as JSON text. JSON does not guarantee better accuracy. Encode line breaks as \n in request JSON. The model's published evaluation results focus on English.
